## Firewall Rules

### pfSense / HAProxy

HAProxy runs on pfSense (192.168.1.1) and proxies:

- `media.<domain>` → Jellyfin (r730xd:8096)
- `vaultwarden.<domain>` → Vaultwarden (r730xd:8222)
- `grafana.<domain>` → Grafana (r730xd:3000)
- `homepage.<domain>` → Homepage (r730xd:8080)
- `prometheus.<domain>` → Prometheus (r730xd:9090)

Backend health checks ensure services are available before routing traffic.

### nftables (per-host)

Each server runs nftables via NixOS `networking.firewall`:

- **Default policy**: drop unmatched inbound traffic.
- **Reverse-proxy backends**: only the HAProxy gateway IP may reach ports declared in `networking.proxyBackendPorts`.
- **Monitoring**: only the Prometheus server IP may reach `node_exporter`.
- **PostgreSQL**: only Matrix Synapse on `r730xd` may reach PostgreSQL on `r820` at port 5432.
- **SSH**: port 22 is available according to the shared SSH access policy.
- **Other service ports**: closed to direct LAN access unless a module explicitly documents and adds a narrower exception.

Backend ports are centrally generated by `modules/features/reverse-proxy-backends.nix` from `networking.proxyBackendPorts`. Services should declare their backend port there rather than adding a duplicate `extraInputRules` entry.

## Reverse-proxy exposure

`networking.internalOnlyPorts` is the authoritative list of TCP ports that
must never be exposed through the HAProxy backend allowlist.

A feature module may retain a service-specific assertion when its error message
is materially clearer. It must not introduce a second, divergent definition of
“internal-only.”

To make a service internal-only:

1. Add its port to `networking.internalOnlyPorts`.
2. Do not add that port to `networking.proxyBackendPorts`.
3. Add a service-specific assertion only if it improves the failure message.

To expose a service through HAProxy:

1. Add its port to `networking.proxyBackendPorts`.
2. Ensure the service is intended to be reachable through the reverse proxy.
3. Ensure any required authentication, authorization, or rate-limiting policy
   is owned by the service module.

### Grafana storage

Grafana runs on `r730xd` and uses its local SQLite database at `/var/lib/grafana/data/grafana.db`. PostgreSQL on `r820` is the central database host for services that explicitly configure a PostgreSQL backend, such as Matrix Synapse.

### Security Properties

The `tests/firewall.nix` VM test enforces, with a stand-in service on a backend port:

1. A **backend port** listed in `networking.proxyBackendPorts` is reachable from the HAProxy gateway only, not from other LAN hosts
2. **node-exporter** (port 9100) is reachable from the Prometheus host only
3. The `input-allow` chain contains no rule that is a bare verdict

Run the test with (needs KVM):

```bash
nix build --print-build-logs .#firewall-isolation
```

It is not part of `nix flake check`; see `tests/README.md`.

## Monitoring Network Flow

- **Prometheus** (r730xd:9090) scrapes:
  - node-exporter on all hosts (9100)
  - Blackbox exporter for external probes
  - Service metrics (Jellyfin, Vaultwarden, PostgreSQL)

- **Grafana** (r730xd:3000) visualizes Prometheus data

- **Alertmanager** sends notifications via configured routes

## DNS

Internal DNS is provided by pfSense (192.168.1.1). Hosts are registered via DHCP static leases.

## Troubleshooting

### Check Firewall Rules

```bash
# List nftables ruleset
sudo nft list ruleset

# Check allowed ports
sudo nft list table inet filter
```

### Test Port Reachability

```bash
# From another host (LAN)
nc -zv <host> <port>

# Check listening services
ss -tlnp | grep <port>

# Test HAProxy backend
 curl -v http://<host>:<port>/health
```

### HAProxy Debug (on pfSense)

```bash
# Check HAProxy status (pfSense web UI or SSH)
# Status page: https://192.168.1.1/haproxy/haproxy_listeners.php
# Logs: System > Logs > HAProxy
```

### Prometheus Debug

```bash
# Check scrape targets
 curl http://localhost:9090/api/v1/targets

# View logs
journalctl -u prometheus -f
```

### NAS Mount Issues

```bash
# Check CIFS mount
mount | grep cifs

# Test connectivity
smbclient -L //192.168.2.10 -U <user>

# Check credentials file
ls -la /run/secrets.d/cifs-credentials
```
